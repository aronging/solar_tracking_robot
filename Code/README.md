# MXET 345 solar tracker

This software turns a pan-tilt solar panel on the lab robot to follow the sun.

- The Pi calculates the sun position from the clock and points the panel at it.
- The Pi finds the power peak from the short-circuit current of the panel.
- Every 12 minutes, a scan around the predicted sun position measures the pointing errors of the rig. The tracker uses these values to correct its aim.
- The wheels move one time per session, to turn the robot to face south.

All 193 tests pass against the simulator. Nobody has run the real hardware backend on the robot yet.

## Folder map

Open this `Code/` folder in VS Code on the Pi.

```
Code/
  README.md              this guide
  .vscode/               VS Code settings and tasks. The task numbers agree with the steps below.
  config/default.toml    every setting and its default value. Do not edit this file.
  config/robot.toml      the only file that you edit (channels, site, signs, offsets). Git tracks it.
  lab/                   the lab scripts, not changed. The tracker imports motor_servo_pwm.py and sensor_module.py.
  solar_tracker/         the tracker (python -m solar_tracker <command>)
  analysis/              scripts that make the report figures from the logs
  tests/                 pytest tests. They run against the simulator.
  docs/                  decisions.md, method_code_map.md
```

How the configuration works:

- The tracker loads `config/default.toml`, then `config/robot.toml`. Commands do not need `--config`.
- `--set section.key=value` changes one value for one run. Example: `--set panel.zero_offset_mA=1.2`.
- `--hardware sim` runs a command against the simulator. The robot is not necessary.
- Put global options before the command. Example: `python -m solar_tracker --hardware sim preflight`.
- The real backend does not start until robot.toml has the mux channels and the servo channels. The tracker never guesses a channel.

## Setup, in order

Do the steps in the given order. A step that has a VS Code task gives the task name.

- To run a task, select Terminal > Run Task. Then select the task name.
- To type a command, open the VS Code terminal (Terminal > New Terminal). It opens in `~/mxet345_project/Code`.
- If the prompt does not start with `(env)`, run `source ~/env/bin/activate` first.

### Part A. Laptop (one time)

**Step 1. Install VS Code.**

1. Install VS Code.
2. Install the extensions "Remote - SSH" and "Python". Microsoft makes both.
3. Make sure that a Remote Explorer icon shows in the left bar.

**Step 2. Connect to the Pi.**

1. Connect to the lab Wi-Fi `mxet_Lab`, or connect an Ethernet cable.
2. Push F1. Run "Remote-SSH: Connect to Host...". Type this address:

   ```
   pi@192.168.1.2xx
   ```

   `xx` is your team number.
3. If VS Code asks for the platform, select "Linux". Type the Pi password.
4. Make sure that `SSH: 192.168.1.2xx` shows in the bottom-left corner.

If the connection times out, do these steps:

1. Open the laptop user settings (F1, "Preferences: Open User Settings (JSON)").
2. Add `"remote.SSH.useLocalServer": false`.
3. Connect again.

### Part B. Pi (one time)

**Step 3. Clone the repository and open the folder.**

1. Open a terminal (Terminal > New Terminal). This terminal runs on the Pi.
2. If `~/mxet345_project` exists, rename it: `mv ~/mxet345_project ~/mxet345_project_old`.
3. Run:

   ```bash
   git clone https://github.com/aronging/solar_tracking_robot ~/mxet345_project
   ```

   The repository is private. The VS Code terminal uses the GitHub sign-in of the laptop, so the clone works there. The clone may not work in a plain SSH session.
4. Select File > Open Folder. Type `/home/pi/mxet345_project/Code`. Click OK.
5. When VS Code asks you to install the recommended extensions, accept. This installs the Python extension on the Pi.
6. Make sure that `README.md`, `config/` and `lab/` show in the Explorer.

**Step 4. Install the Pi packages.** Task "4 Install Pi packages".

```bash
~/env/bin/pip install -r requirements-pi.txt
```

- This step needs internet one time. The lab image probably does not have the INA219 package.
- For each package, you see `Successfully installed ...` or `Requirement already satisfied`.

The analysis scripts in steps 10, 11 and 15 also need matplotlib. Do this check:

1. Run `~/env/bin/python -c "import matplotlib"`.
2. If the command fails, run `~/env/bin/pip install matplotlib`. Or, do those three steps on the laptop.

### Part C. Wiring into config/robot.toml (robot on a stand, wheels off the ground)

Connect the panel sensor and the servos first. Use steps 1 to 7 of the [Electrical Assembly Guide](../docs/Electrical%20Assembly%20Guide.md). Measure the servo V+ rail before you connect a servo.

> **Warning:** `lab/test_motor.py` turns both wheels. It also moves servos 12 and 13 through 0 to 180 degrees.
> Run it only when the wheels are off the ground and the servo horns are not installed.
> Step 8 installs the horns. After step 8, do not run `lab/test_motor.py` again unless you remove the horns.

**Step 5. Find the mux channels.** Task "5 Scan mux channels (lab)".

```bash
python lab/sensor_scan.py
```

The script shows one line for each mux channel. Example: `Channel 6:['0x28']`.

- The INA219 (panel) shows as `0x41`.
- The BNO055 (IMU) shows as `0x28`.
- Other lab sensors also show: APDS9960 as `0x39` and VL53L4CD as `0x29`.

In `config/robot.toml`, set these keys:

- `hardware.mux_channel_panel`: the channel that shows `0x41`. This key is a comment until you set it.
- `hardware.mux_channel_imu`: the channel that shows `0x28`. The prefilled value is 6, from `lab/test_sensor.py`.

If `0x41` does not show, use the troubleshooting table in the Electrical Assembly Guide.

**Step 6. Check the servo channels and the site.** No task.

1. Look at the servo HAT. Make sure that the pan servo connects to `hardware.servo_channel_pan` (prefilled 13).
2. Make sure that the tilt servo connects to `hardware.servo_channel_tilt` (prefilled 12). These two values come from `lab/test_motor.py`.
3. If the pan and tilt channels are reversed, swap the two numbers in robot.toml. Do not move the plugs.
4. Check the `[site]` section: `name`, `lat_deg`, `lon_deg` and `declination_deg`. East is positive for the longitude and the declination. The default values are for College Station.
5. Find the declination for your site and date with the [NOAA magnetic field calculator](https://www.ngdc.noaa.gov/geomag/calculators/magcalc.shtml).
6. Write the source of the declination in [docs/decisions.md](docs/decisions.md).

### Part D. Tracker checks

Each check is a VS Code task. Each task runs `python -m solar_tracker <command>`. If you push Ctrl-C in the terminal, the tracker parks the servos, stops the wheels and closes the logs.

**Step 7. Preflight.** Task "7 Preflight".

```bash
python -m solar_tracker preflight
```

Preflight does these checks:

- It scans the I2C bus.
- It reads the panel and the IMU.
- It checks the clock and calculates the sun position.
- It moves each servo 20 degrees and back.

The output has the lines `i2c`, `panel`, `imu`, `clock`, `sun` and `preflight_ok`. The last line is `exit: done`.

Correct each problem that preflight shows:

- `CONFIG ERROR: ...` gives the name of the robot.toml key that is missing or incorrect.
- `panel_warning ... negative current` means that the panel wires are reversed.
- `imu_warning ... magnetometer calibration` means that the IMU is not calibrated. Move the robot in figure-eights. Hold it still on each face. Then run preflight again. The tracker skips the coarse turn (step 12) until `cal_mag` is 3 or more.
- `ntp_synced=false` means that the Pi clock is not synchronized. Compare `date -u` with a phone. A clock error of one minute causes a pointing error of 0.25 degrees.

**Step 8. Center the servos.** Task "8 Park (centre servos)".

```bash
python -m solar_tracker park
```

1. Both servos move to the park position (center, 1500 µs) and stop. The last line is `exit: done`.
2. Install the servo horns now, while the servos are centered. Use the procedure in the assembly guide.

**Step 9. Check the servo directions.** Tasks "9a Check pan sign", then "9b Check tilt sign".

```bash
python -m solar_tracker calibrate-servo --servo pan --check-sign
python -m solar_tracker calibrate-servo --servo tilt --check-sign
```

The servo moves to -20, 0, +20 and 0 degrees. At each position, it waits until you push Enter.

- Positive pan must turn the panel clockwise, as seen from above.
- Positive tilt must lift the panel normal.
- If a direction is incorrect, set `servo.pan_sign = -1` or `servo.tilt_sign = -1` in robot.toml. Do not swap the wires.

**Step 10. Calibrate the servos.** Tasks "10a Calibrate pan" and "10b Calibrate tilt", then "10c Fit servo calibration".

```bash
python -m solar_tracker calibrate-servo --servo pan
python -m solar_tracker calibrate-servo --servo tilt
python analysis/fit_servo_cal.py logs/<log folder>/servo_cal.csv
```

1. The servo moves through its pulse range in 100 µs steps, first up and then down.
2. At each prompt (`pan up 1100 us -> measured angle`), measure the angle with a protractor or a phone inclinometer. Type the angle.
3. To skip a point, push Enter with no value. To stop, type `q`.
4. Each calibration run shows its log folder. Example: `logs/20261124_150000Z_calibrate-servo`.
5. Run the fit one time for each of the two folders. Task 10c asks for the folder. The fit merges the data for the two servos.

The fit shows a slope, an intercept, the residual RMS and the hysteresis for each servo. It writes `config/servo_cal.json`, and the tracker uses this file automatically. You do not set a robot.toml key. Git ignores this file, so it is only on this Pi.

**Step 11. Set the panel current to zero.** Task "11 Panel zero (cover panel)".

1. Cover the panel fully, for example with a box.
2. Run:

   ```bash
   python -m solar_tracker static-log --minutes 1
   python analysis/noise_model.py --log logs/<log folder>/static.csv
   ```

   The first command records the current at 10 Hz for one minute. The second command shows `mean_mA`.
3. Set `panel.zero_offset_mA` in robot.toml to that mean value.
4. The tracker subtracts the old `zero_offset_mA` from the logged current. If the old value was not 0.0, add the mean to the old value.
5. Remove the cover. Put the panel below a lamp. Run step 7 again.
6. Measure the panel current with a multimeter in current mode. Compare the sign and the value with `panel isc_mA`.

**Step 12. Check the wheels.** Task "12 Bench turn (wheels off ground)", then two commands that you type.

Keep the robot on the stand with the wheels off the ground. robot.toml has these prefilled wheel settings:

- `drive.left_motor_channels = [0, 1]` and `drive.right_motor_channels = [2, 3]`. These are the `PWM_Motor(0, 1)` and `PWM_Motor(2, 3)` pairs in `lab/test_motor.py`.
- `turn_sign = 1`.

Nobody has confirmed which pair drives the left wheel.

1. Do a bench turn. The wheels do not move. The PID turns a simulated robot from the real IMU heading.

   ```bash
   python -m solar_tracker coarse-turn --bench
   ```

   The output has `coarse_align success=true reason=in tolerance` and `exit: done`.

2. Turn the real wheels, with the wheels off the ground.
   1. Read `heading_true_deg` in the `imu` line.
   2. Calculate a target 90 degrees clockwise from that heading. If the result is more than 360, subtract 360.
   3. Run:

      ```bash
      python -m solar_tracker coarse-turn --robot-on-ground --target <heading + 90>
      ```

   4. The wheels turn. The robot cannot turn on the stand, so the wheels continue for a maximum of 40 s. When you see the direction, push Ctrl-C.

   For a clockwise turn, the left wheel must go forward and the right wheel must go backward. Change robot.toml until you see this result:

   | Result | Change in robot.toml |
   |---|---|
   | The "left" channels drive the right wheel | Swap `drive.left_motor_channels` and `drive.right_motor_channels` |
   | One wheel turns in the incorrect direction | Set `drive.left_sign` or `drive.right_sign` of that wheel to -1 |
   | Both wheels turn in the incorrect direction | Set `drive.turn_sign = -1` |

   The right motor is probably installed in the opposite direction, because `lab/test_encoder.py` counts it as negative for forward movement. Thus you will probably need `right_sign = -1`.

   If you cannot see which pair drives which wheel, run `lab/test_motor.py`. It drives the two pairs forward, then backward. Read the warning in Part C before you run it.

3. Do a turn on the ground.
   1. Put the robot on the floor, with clear space around it.
   2. Run:

      ```bash
      python -m solar_tracker coarse-turn --robot-on-ground
      ```

   3. The robot must turn to face south (180 degrees true) and stop. The output must have `coarse_align success=true`, and `heading_true_deg` must be within 2 degrees of 180.

### Part E. Run

**Step 13. Lamp demonstration (indoors).** Task "13 Lamp demo".

```bash
python -m solar_tracker lamp --seconds 300
```

1. Put a lamp in front of the panel.
2. The tracker finds the lamp, then makes the peak more accurate with a cosine-fit scan.
3. Move the lamp. When the current decreases by 5%, the tracker finds the lamp again.

The output has acquire lines and scan lines. After 300 s, the last line is `exit: duration reached`.

**Step 14. Track the sun (outdoors).** Task "14 Track (robot on ground)".

```bash
python -m solar_tracker track --robot-on-ground
```

1. Put the robot on level ground in full sun.
2. The robot turns to face south and finds the sun.
3. The tracker follows the sun. Every 12 minutes, it does a scan to measure the pointing offsets.

The run stops when the sun is below 10 degrees elevation. Or, set a time limit with `--duration-min` (example: `--duration-min 60`). Ctrl-C also stops the run correctly.

- To skip the wheels, aim the robot south by hand. Then run `track --skip-turn`.
- If the clock is not synchronized with NTP, track does not start. Compare `date -u` with a phone. Then add `--ack-clock`.

**Step 15. Analyze the log.** Task "15 Analyze latest log". This task uses the newest folder in `logs/` (`analyze latest`).

```bash
python -m solar_tracker analyze logs/<log folder>
```

This command runs each analysis script that has data in that folder. The figures and CSV files go into `logs/<log folder>/analysis_out/`.

After each session, copy `logs/` from the Pi. Step 5 of "Everyday use" gives the procedure.

Other tasks: "Run tests" (`python -m pytest -q`) and "Sim day (no hardware)" (`python -m solar_tracker sim-day`).

## Everyday use

1. Start the robot. Connect to `mxet_Lab`, or connect an Ethernet cable.
2. In VS Code, push F1. Run "Remote-SSH: Connect to Host..." and type `pi@192.168.1.2xx`.
3. VS Code opens the last folder. If it does not, select File > Open Folder and type `/home/pi/mxet345_project/Code`.
4. In the terminal, run:

   ```bash
   cd ~/mxet345_project/Code
   git pull
   ```

   If `git pull` stops because `config/robot.toml` has local changes, run `git stash`, `git pull` and `git stash pop`. Then check robot.toml.
5. Indoors, run task "13 Lamp demo". Outdoors, run task "14 Track (robot on ground)".
6. Copy the logs from the Pi. Git ignores `logs/`, so `git pull` does not copy the logs. Use one of these methods:
   - In the VS Code Explorer, right-click `logs` and select Download.
   - On the laptop, run:

     ```bash
     scp -r pi@192.168.1.2xx:~/mxet345_project/Code/logs .
     ```

When you change `config/robot.toml` on the Pi, commit and push it. Then the team has the same settings.

To work on the laptop without the robot (Windows), run these commands. On Linux, use `.venv/bin/python`.

```
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements-dev.txt
.venv/Scripts/python -m pytest -q
.venv/Scripts/python -m solar_tracker --hardware sim preflight
```

The tracker on the Pi needs only the Python standard library and the Adafruit packages. On Python older than 3.11, it also needs `tomli`. The tracker does not use numpy. Only the analysis scripts need numpy and matplotlib.

## Commands

Run each command as `python -m solar_tracker <command>`.

| Command | Function |
|---|---|
| `preflight` | Scans the I2C bus. Reads the panel and the IMU. Checks the clock sync and the sun position. Moves each servo a small angle. |
| `calibrate-servo --servo pan\|tilt [--check-sign] [--step-us 100]` | Moves the servo pulse up and down in steps. You type the measured angle at each step. Writes `servo_cal.csv`. |
| `static-log --minutes 10 --pan 0 --tilt 30` | Holds a fixed position and records Isc at 10 Hz, for the noise model. |
| `coarse-turn --robot-on-ground \| --bench [--integral euler\|trapezoid\|simpson] [--target 180]` | Does only the PID turn. |
| `acquire --mode sun\|lamp` | Does only the acquire. |
| `lamp --seconds 300` | Indoor demonstration. Finds the lamp and refines the peak with a cosine fit. Finds the lamp again when Isc decreases by 5%. |
| `track --robot-on-ground \| --skip-turn [--ack-clock] [--k-mA] [--duration-min] [--spread]` | Runs the full session. |
| `park` | Moves the servos to the park position. |
| `analyze <log folder> \| latest` | Runs each analysis script that has data in that folder. Writes the output to `<log folder>/analysis_out/`. |
| `sim-day [--seed] [--true-az-offset 7] [--true-el-offset -3] [--clouds 9000:10200:0.3] [--hours 6]` | Simulates one day with known errors. It takes approximately 6 s. |

- To run a command against the simulator, add `--hardware sim` before the command.
- `lab/motor_servo_pwm.py` sets the PCA9685 to 100 Hz. The tracker does not check or change this frequency.
- If you push Ctrl-C, the tracker parks the servos, stops the wheels and closes the logs.

## Logs

Each run makes a folder `logs/YYYYMMDD_HHMMSSZ_<command>/`. The folder has these files:

- `session.json`: the configuration, the software versions, the final offsets and the exit reason.
- `cycle.csv`: one row each second.
- `scan.csv` and `scan_fit.csv`: the refine scans.
- `events.jsonl`, `run.log`, `acquire.csv`, `turn.csv`, `fixed_check.csv`, `static.csv` and `servo_cal.csv`.

`solar_tracker/logging_.py` gives the columns of each CSV file. On the real hardware, the logger writes each row to the disk immediately, because the Pi can lose power. After each session, copy `logs/` from the Pi.

## Figures for the report

Each script writes to `analysis_out/<script>/`, shows its key numbers and accepts `--seed`.

- Without `--log`, the scripts that use a session run a simulated day. Thus you can make every figure now.
- For hardware data, give `--log <session folder>` or the CSV file.

| Script | Method | Shows |
|---|---|---|
| `kepler_convergence.py` | 1 | Fixed-point (linear) and Newton (quadratic) convergence at e = 0.0167, 0.5 and 0.9 |
| `prediction_vs_measured.py` | 1 | The model against the NOAA reference (maximum 0.024 deg). The measured peak against the prediction. |
| `sunrise_roots.py` | 6 | Bisection and false position |
| `fit_servo_cal.py <csv>` or `--demo` | 2 | Line fits from PWM to angle, and the hysteresis |
| `golden_convergence.py` | 3 | The 0.618 shrink rate. The error against the noise, with and without the parabola. |
| `cosine_fit_study.py` | 4 | The condition number and the peak scatter against the scan spread |
| `offset_convergence.py` | 2 and 4 | The learned offset against the number of scans, compared with the simulator truth |
| `pid_study.py [--log turn.csv ...]` | 5 | Euler, trapezoid and Simpson integration. The gain and stability map. |
| `tracking_gain.py` | trapezoid and Simpson | The energy compared with a virtual fixed panel |
| `noise_model.py`, `plot_session.py` | none | The sensor noise. A session overview. |
| `method_code_map.py` | none | Writes `docs/method_code_map.md` (method, file, lines, test, script) |
